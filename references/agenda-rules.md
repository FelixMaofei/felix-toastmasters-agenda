# Toastmasters 会单业务与时间规则

## 1. 会单是什么

会单是俱乐部基于 Toastmasters 共通规则和本期实际安排，对本次会议作出的最终运行承诺，并以可现场执行、可打印、可传播、符合品牌规范的成品发布出来。

它不是漂亮表格，也不是历史样式复刻。

## 2. 信息优先级

```text
本期用户明确确认
> 本期角色接龙和会议说明
> Toastmasters 共通规则
> 俱乐部名称、默认地点和语言
> 通用默认时长
```

旧会单是可选的初始化参考，不是必交材料。当前附件已经有旧会单时，可用它识别俱乐部名称、默认地点、语言、当届官员和常用固定信息组件的候选值；没有旧会单就从当前接龙和消息继续。只有用户确认后才保存；任期官员须确认仍为当届，旧会单中出现过某组件不自动等于俱乐部的长期选择。

不要继承旧会单中的本期角色、会议号、历史时间错误或视觉样式。二维码不从旧 PDF/截图裁切或重建，仍由用户提供原始图片文件。

## 3. 面向 AI 小白的协作规则

普通用户只需提供角色接龙、本期说明和已有附件，再用自然语言说明想要的修改。AI 负责理解、整理和调用生成器；不把内部数据结构、排版实现、程序权限或安装路径变成用户的学习任务。

### 3.1 最短入口与附件识别

用户说“帮我把这份角色接龙做成会单”就是开始指令。先检查当前消息、图片、旧会单和其他附件，已经出现的事实不再询问。旧会单只是可选参考；没有旧会单也要继续。

### 3.2 一次合并询问

只问“无法从当前材料判断，并且会改变会议承诺”的信息。同一轮中先用人话说明已识别出什么和当前所处阶段，再将所有真正缺项合并成一次短询问。

必要问题与可选增强必须分开。必要项提供编号和一条可直接照抄的回答格式；最后补一句“是否还有其他希望呈现在会单上的？例如 Pathways、俱乐部介绍、入会信息或二维码；不补也可以先生成”。不依赖专用提问工具，不逐题发送按钮或一次只问一个。

当前消息或 profile 已明显暴露必要缺项时，立即提问并结束本轮；不要先读详细规则、计算整场时间或创建文件。日期中的星期只有用户提供或程序验证后才添加。

通常只有以下情况需要问：

- 多个俱乐部无法唯一匹配，或俱乐部名称、实际日期时间地点无法判断；
- 接龙明确出现某个环节，但负责人待定；
- 本期特殊环节缺少负责人、时长或相对位置；
- 会议必须超时，需要用户确认准确的超时分钟数；
- 完整内容与“一页 A4 且清晰可读”冲突，需要用户决定内容取舍。

不要默认追问审美喜好、旧会单、主题、今日一词、Pathways、二维码、介绍文字、技术实现或本来就能由生成器计算的数字。如果后续因用户新增内容才产生新冲突，可再针对该冲突询问，不要重新发整份问卷。

语言能从当前材料明显判断时直接采用。固定信息区优先继承 profile；新俱乐部尚未选择时，本期初版采用“时间官规则、头马介绍、会议边界”，当届官员只有在名单已提供时才加入。这个一次性选择不写入长期 profile，用户可以在看图后增删。

### 3.3 必要信息后直接出图

信息足够后，程序先生成自然语言可读的文字会单，AI 自己核对本期环节、负责人、顺序、时长、地点和固定信息。除非用户明确要求先看文字稿，否则不把整篇 Markdown 发给用户并要求回复“确认”；核对通过后直接生成真实 A4 图片初版。

图片出来后，用户再判断是否清楚、好看。用户说“这期改成……”时回到内容层重新计算；说“字大一点”“这块小一点”时只改视觉意图并重新预览。两类修改都已经是本期可恢复调整的授权，不再向普通用户请求修改 CSS、JSON、HTML 或 Python 的权限。

用户说“直接导出”“生成吧”“OK”“可以”“就这样”或同义表达时，立即交付当前预览对应的 PDF/PNG，不再追加确认、重新渲染或自行继续优化。

修改失败、导出超过一页或视觉检查未通过时，保留上一份可用 PDF/PNG，用人话说明哪个目标与单页容量冲突，再给 1–2 个可操作选择。不能让用户从“已有成品”退回“什么都没有”。

### 3.4 三种用户视角

- **AI 小白**：只用人话交流，默认不展示内部字段、命令和实现细节。
- **进阶用户**：明确要求查看时，可展示环节、时长、信息组件和计算结果，仍不要求其编辑内部文件。
- **维护者**：只有用户明确要求修改 Skill 本身、跨俱乐部的内置默认或排查源码故障时，才进入实现层。

用户明确说“以后默认都这样”时，才更新俱乐部的长期设置；“这期”“这次”或单纯视觉反馈默认只影响当前成品。

本期明确事实与 profile 不一致时，本期事实直接优先，不向普通用户推测“代班/轮值”等原因，也不展示 profile 命令。只有用户要求长期沿用时才进入 profile 更新。

## 4. 四类内容

### 4.1 标准环节

默认保留，只有本期明确取消时才删除：

1. 规则介绍
2. 会长致辞
3. 总主持开场
4. 嘉宾介绍
5. 合影／中场休息／茶歇
6. 真情分享
7. 颁奖
8. 闭幕致辞

标准负责人：

- 会长致辞、闭幕致辞：默认现任会长；本期明确指定其他人时覆盖。
- 嘉宾介绍、真情分享：没有明确负责人时询问，不从事务官、总主持、会议经理或其他角色猜测。
- 合影／中场休息／茶歇：优先填写本期拍照官。拍照官来自幕后团队，但可作为既有合影环节的负责人。

### 4.2 角色触发环节

- 时间官：时间官宣言 + 时间官报告。
- 哼哈官：哼哈官宣言 + 哼哈官报告。
- 语法官：语法官宣言 + 语法官报告。
- 备稿演讲者：一项备稿演讲。
- 备稿点评人：与对应编号的备稿演讲绑定。
- 即兴主持：即兴演讲。
- 即兴点评人：即兴点评。
- 总点评：总点评报告。

角色行出现但姓名未定，表示环节存在、负责人未完成。角色行完全没有出现，表示本期不生成该角色对应环节。

### 4.3 本期特殊环节

AI 领航、工作坊、微课、圆桌论坛、比赛、上任仪式、证书颁发等，只有本期资料明确出现才加入。必须有：

- 环节名称；
- 负责人或参与者；
- 在接龙/会议中的相对位置；
- 时长。

负责人必须是真实姓名。不能从总主持、会议经理、事务官或角色称呼猜测，也不能写“Toastmaster”“主持人”“待定”；缺姓名时询问。

### 4.4 幕后角色

拍照官、场控/PPT、打印、签到、物料、投票链接、直播回放等单独显示，不进入时间轴。幕后角色不会自动创造台前环节。

## 5. 默认顺序

本期明确顺序优先；角色接龙通常已经按顺序排列，应尽量保留。只有标准环节未写在接龙里时，才按以下锚点补入：

```text
规则介绍
会长致辞
总主持开场
已报名功能官宣言（按接龙顺序）
嘉宾介绍
本期上半场内容（特殊环节、备稿、即兴，按接龙）
合影／中场休息／茶歇
备稿点评（与演讲编号对应）
即兴点评
已报名功能官报告
真情分享
总点评（如有）
颁奖
闭幕致辞
```

本期资料明确把标准环节放在别处时，按本期安排，不强制搬回默认位置。

## 6. 默认时长

| 环节 | 默认时长 |
|---|---:|
| 会前入场与设备调试 | 30 分钟，不占正式会议 |
| 规则介绍 | 2 分钟 |
| 会长致辞 | 3 分钟 |
| 总主持开场 | 2 分钟 |
| 时间官/哼哈官/语法官宣言 | 每项 2 分钟 |
| 嘉宾介绍 | 5 分钟 |
| 备稿演讲 | 每篇 7 分钟 |
| 破冰演讲 | 6 分钟；明确项目要求优先 |
| 备稿点评 | 每篇 3 分钟 |
| 时间官/哼哈官/语法官报告 | 每项 3 分钟 |
| 合影／中场休息／茶歇 | 5 分钟，可调整 |
| 真情分享 | 6 分钟，可调整 |
| 总点评 | 8 分钟 |
| 颁奖 | 3 分钟 |
| 闭幕致辞 | 2 分钟 |

特殊环节和用户明确时长始终优先。

自动闭合时，合影/休息只在 1-15 分钟内调整，真情分享只在 1-20 分钟内调整；这只是防止程序制造荒谬时长的自动安全范围。用户明确锁定的本期时长可以超出。

## 7. 即兴联动

即兴演讲不设固定硬范围。即兴点评需要覆盖即兴主持和参与者，因此：

```text
即兴点评时长 ≈ 即兴演讲时长 ÷ 2
```

生成器在两项都未锁定时，用剩余时间按 0.5 分钟递增求解，使两者之和闭合，同时让即兴点评尽量接近即兴演讲的一半。在同样可用时，自动分配优先使用整分钟；只在本期事实或时间闭合需要时使用 0.5 分钟。

自动计算时，即兴点评与“即兴演讲 ÷ 2”的偏差不得超过 2 分钟。若其他时长已锁定且因此无法闭合，程序应报告缺口，不能把即兴点评拉长成不合理的填充环节。用户明确锁定了异常时长时，保留本期事实并给出警告。

若用户明确给出参与人数、即兴时长或点评时长，以本期事实为准；程序只检查关系是否明显异常，不擅自覆盖。

## 8. 转场

- 大多数主要环节后：1 分钟。
- 本期明确需要更短转场时，可覆盖为 0.5 分钟；不通过把其他真实转场改成 0 来补数。
- 规则介绍后：0 分钟。
- 会长致辞后：0 分钟。
- 合影／中场休息／茶歇后：0 分钟。
- 最后一项后：0 分钟。
- 本期明确无缝衔接或需要更长技术切换时，可在 JSON 中覆盖。
- 任意已生成环节优先用 `agenda_overrides` 按环节 ID 覆盖转场；旧 `standard_overrides` 和 `transition_overrides` 只为兼容已有输入保留。

转场参与时间计算，但默认不作为会单中的独立可见行。

## 9. 时间闭合

默认正式会议时间窗为 120 分钟。

```text
固定环节与转场 F
+ 即兴演讲 I
+ 即兴点评 E（约 I ÷ 2）
+ 休息 B
+ 真情分享 S
= 本期会议时间窗
```

程序先锁定用户明确给出的时长和固定默认值，再联动计算未锁定的即兴、即兴点评、休息和真情分享。

所有显式环节时长、转场和超时授权都支持 0.5 分钟递增；半分钟时间点显示到 30 秒。

- 正好闭合：AI 完成内部文字核对后，直接进入视觉初版。
- 超时：报告超出分钟数，请用户决定延长或删减。
- 未闭合：报告剩余分钟数，给出可执行分配建议；不得留下无解释空档。
- 任意修改后：从第一行重新计算全部开始和结束时间。

默认不批准超时。只有用户明确同意当前计算所需的准确分钟数后，才能写入 `meeting.approved_overtime_minutes`；布尔值或“继续做”等模糊表达不等于批准延长。内容或时长变化后，若实际超时分钟数不再与授权相同，程序必须阻断并重新确认，不能把旧授权变成新的填充目标。

## 10. 成品标准

- 一份结构化 JSON 是内容真源。
- Markdown、HTML、PDF、PNG 使用同一计算结果；最终必须是 1 页 A4 竖版。内容过长时阻断导出并请用户精简，不跨页、不裁切、不牺牲基本可读性。
- 必须使用完整清晰的 Toastmasters International 官方 Logo / Wordmark / Logo Lockup，不重设、不改色、不拉伸、不加特效，不自创官方 tagline。
- 品牌规范是底线而非固定模板。可在官方品牌色附近大胆设计版式、构图与主题表达，但整体仍需专业、清晰、温暖、自信、国际化。
- 中文使用专业黑体，英文使用现代无衬线字体；避免霓虹色、廉价渐变、卡通配色、手写/复古花体和过度科技感。
- 必要事实确认并完成内部文字核对后，视觉制作不得改变姓名、角色、顺序、时长、地址或标题。
- 新版 PDF/PNG 只有在单页和视觉检查通过后才替换当前成品；未通过时恢复上一份可用版本。

## 11. 固定信息组件

固定内容是可选择的会单组件，不是每张会单都强制出现。

- 程序内置：时间官规则、头马国际演讲会介绍、会议秩序与四类内容禁忌。
- 俱乐部提供：当届官员团队、俱乐部介绍、如何入会、VPM 二维码。
- 本期提供：投票二维码。
- 自定义扩展：Pathways、嘉宾参与规则、俱乐部特色等使用标题+纯文本行的 `custom_support_blocks`，可由排版器自动放置。

固定信息组合优先继承 profile。首次使用且组合未知时，不把它列为必要问题；本期初版默认使用以下有内容可生成的推荐项：

```text
timer_rules
toastmasters_intro
meeting_boundaries
officers（仅当官员名单已提供）
```

这是本期初版的一次性推荐组合，不自动写入长期 profile。用户看图后可以全选、部分选择、增加其他组件，或使用空数组只要纯议程。

取值顺序：

1. `meeting.support_components` 存在：完整采用它，包括 `[]`；
2. 否则 `club.support_components` 存在：完整采用它，包括 `[]`；
3. 两处都不存在：为本期 meeting 写入上述可生成的推荐组合；
4. 单期数组是完整覆盖，不与俱乐部数组合并。

`[]` 只不显示固定信息区，不删除标准议程环节。用户说“以后通常都要”时写入 `club.support_components`；说“只改这一期”时写入 `meeting.support_components`。

二维码必须使用用户提供的原始图片文件并原样嵌入；不得让图片模型生成、改写或修复二维码。

固定信息排版不依赖某一组组件的写死位置，也不按会议类型切换模板。内容层把每个组件的真实正文写入计算结果；视觉意图只把它们分为“现场运营信息”和“背景信息”并安排同组顺序；单一 renderer 根据真实尺寸进入自然文档流。有内容才生成，不保留空栏、空卡或组件内部死空白。实际 PDF 超过 1 页时仍必须阻断。
